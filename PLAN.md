## 1. Analysis of the original spec

### 1.1 Biggest problem: the original spec's Arcade integration targets arcade.dev

| Item in the spec | Actually belongs to | Status |
|---|---|---|
| Arcade JS SDK, `arcade.tools.execute({tool_name, user_id})` | arcade.dev | no key, and not the hackathon host |
| `GoogleShopping.SearchProducts`, SERP key, dashboard authorization | arcade.dev | same |
| The story "the agent calls external tools as the user, with authorization managed by Arcade" | arcade.dev | arcade.ai has no such feature; judges would not follow |

The arcade.ai API is **prompt → pattern → physical product → checkout**, verified today with curl (results in `samples/`):
`patterns/create` (about 90 seconds) → `products/create` (about 10 seconds, returns mockup images + real unit price + maker) → `checkouts/create` (returns a payable URL).

### 1.2 Switching to arcade.ai makes the demo stronger

Originally the concept agent could only "search similar products and edit JSON", so judges would see a text diff.
With arcade.ai, the agent's Proposal carries:

- Real patterns and pillow / scarf / lampshade mockup images generated by arcade.ai
- Real manufacturable specs (fabric, size) and a real unit price (USD) from arcade.ai
- The real maker's name from arcade.ai (for example Esme)
- After Release, the "Open store" button returns an arcade.ai payment URL (`checkout.arcade.ai`), so judges can see an orderable page on the spot

### 1.3 Other adjustments

| Item | Original spec | Adjustment |
|---|---|---|
| "Proposal appears within 30 seconds of the mention" | 30 seconds | arcade.ai pattern generation takes 90 seconds. Change to: the LLM posts a "here is what I plan to do" Message within 15 seconds, and the Proposal appears within 2 minutes. `/agent-runs/:id` also returns `stage` so the frontend can show progress. |
| Shopify store | Call Admin GraphQL directly | No dev store or token yet. Main path becomes arcade.ai `checkouts/create`; Shopify is a stretch goal. |
| ProductSpec | No Arcade fields | Add an `arcade` block (see §3); `images[]` holds arcade.ai mockup images; `price_target` is filled from `unitPrice`. |
| LLM call | `tool_choice: {type: 'any'}` | Current Claude models (Opus 5.5 / Sonnet 5.5) no longer accept forced `any` and return 400. Use `tool_choice: auto` + `strict: true` on tools + a system prompt that says "deliver only via submit_spec". |
| LLM credentials | Not mentioned | The backend calls Claude through the Anthropic SDK and needs `ANTHROPIC_API_KEY` (see §10). This is separate from the arcade.ai key. |
| Currency | TWD | arcade.ai returns USD; `price_target.currency` becomes USD. |

## 2. Adjusted demo script (5 minutes)

1. Create Brand "Mist" (identity: East Asian ink wash, understated, sage gray and cream palette) and Product "Tea Garden Pillow" with an initial ProductSpec (text only, no images).
2. Type `@agent:concept make a spring edition: add plum blossoms, use 20x20 linen` in the thread.
3. The UI polls every 2 seconds: `designing` (Claude writes the spec and prompt) → `generating` (arcade.ai generates the pattern) → `building` (arcade.ai builds the product) → `done`.
4. The Proposal appears: side-by-side diff, with arcade.ai mockup images, USD unit price and maker on the right. Click merge (as u_bob); coauthors show alice, bob and the concept agent (on behalf of alice).
5. Click Release, then "Open store", get the `checkout.arcade.ai` URL and open it for the judges.

## 3. New ProductSpec fields

```json
{
  "...": "all original spec fields are kept",
  "price_target": {"currency": "USD", "min": null, "max": null},
  "arcade": {
    "modelId": "chinoiserie",
    "prompt": "English prompt the agent writes for arcade.ai",
    "patternId": "",
    "categoryId": "",
    "selections": {"fabric": "linen", "size": "20x20", "embellishment": "none", "insert": "none"},
    "productId": "",
    "unitPrice": {"amount": "43.56", "currency": "USD"},
    "maker": {"makerId": "", "name": ""}
  }
}
```

Every id under `arcade.*` is returned by arcade.ai.

### 3.1 All images come from arcade.ai

Every product image in the system is generated by arcade.ai; no other image generation service is used:

| role | Source | arcade.ai endpoint |
|---|---|---|
| `pattern` | the pattern itself, 1024x1024 PNG | `imageUrl` from `patterns/get` |
| `hero` | front mockup of the product | `images[0].url` from `products/get` |
| `closeup` | closeup mockup of the product | `images[1].url` from `products/get` |

Edits (`refine/edit`, `recolor`, `crop`, and so on) each produce a new pattern, so images of iterated versions are all from arcade.ai too. If a Brand needs a representative image, it is generated with `patterns/create` as well. The only images not produced by arcade.ai are user-uploaded reference images, which are sent into arcade.ai as input via `references/createUpload`.

arcade.ai returns signed image URLs that expire. The backend downloads each image immediately to `data/images/<id>-<role>.png` and serves it through `GET /images/:file`; `images[].url` in the ProductSpec always points at our own path. Images stay valid during the demo, and the URLs in the export_payload for Shopify are stable.

## 4. concept agent (replaces the GoogleShopping version)

### 4.1 Tools

Tools given to Claude (Anthropic tool_use, `tool_choice: auto`, every tool `strict: true`):

| tool | What it does | Implementation (all call arcade.ai) |
|---|---|---|
| `list_styles` | returns the 26 arcade.ai style models | `models/list`, cached at startup |
| `list_categories` | returns the 21 print categories and 8 jewelry categories on arcade.ai | `categories/list`, cached at startup |
| `get_category_options` | returns the fabric / size options for a category | `categories/get` with `selections: {}` |
| `submit_spec` | delivers the new ProductSpec + summary + arcade prompt + categoryId + selections | local, zod validation |

Claude never waits for images; it only "designs". Generation is run by the backend on arcade.ai after `submit_spec`.

### 4.2 `runConceptAgent(runId)` steps

1. Load the AgentRun, input Revision, Brand, and the last 10 Messages. stage = `designing`.
2. Claude tool loop (at most 8 rounds) until `submit_spec`. On zod validation failure, send the error back once.
3. Immediately post an agent Message: "I will generate Y in style X, as a W-size Z".
4. stage = `generating`: arcade.ai `patterns/create` with `prompt`, `modelId`, `categoryId` (one job produces both pattern and product, saving a round trip). If Claude specified non-default selections, use `patterns/create` (without categoryId) → `products/create` instead.
5. Poll `jobs/get` every 3 seconds, up to 4 minutes. stage = `building` once the pattern is ready and the product is still running.
6. arcade.ai `products/get` for mockup images, unitPrice and maker; write them into the spec's `arcade` and `images`.
7. Open branch `agent/concept/<first 8 chars of run id>` → Revision (author=agent, on_behalf_of=the user who triggered it) → Proposal(open) → agent Message describing the change → AgentRun succeeded.
8. Any exception → failed + error + a failure Message. On a 4xx from arcade.ai, copy its message verbatim into error.

### 4.3 System prompt essentials

- You are the product concept designer on the brand's co-creation team; deliver only via `submit_spec`.
- Call `list_styles` and `list_categories` first to pick a style and category, then `get_category_options` to confirm the size and material exist.
- Write `arcade.prompt` in English, describing the scene and style; do not include the product name.
- Keep fields the user did not ask to change as they are; keep existing ids on array elements and give new ones new ids.
- Write name, tagline and concept in the Brand identity's voice (English).
- summary in English, at most three sentences: what changed, which style and category were chosen, and why.

The arcade.ai path patterns/create → products/create → checkouts/create was run end to end with curl today; logs are in `.arcade-api/log/`.
No need to spend another 15 minutes on a smoke test; that time goes to the agent.

## 10. Needed before starting

### Two keys, two jobs

| Key | Used by | Status |
|---|---|---|
| `ARCADE_API_KEY` | the backend calling arcade.ai to generate patterns, products and checkouts | in `.env`, verified |
| `ANTHROPIC_API_KEY` | the backend's concept agent calling Claude to design the ProductSpec and write the arcade.ai prompt | not yet available |

Why `ANTHROPIC_API_KEY` is needed: the spec says the LLM is "called directly through the Anthropic SDK, using tool_use to force ProductSpec JSON". That code runs inside our own Hono server, triggered by `POST /products/:id/messages`; when a judge clicks during the demo, Claude is called. This Claude Code conversation window cannot be called by the server as an API, so the server needs its own credentials.

Two ways to get one:

1. Create a key at https://console.anthropic.com/settings/keys and put it in `ANTHROPIC_API_KEY` in `.env`.
2. Install the Anthropic CLI and run `ant auth login`; the SDK then reads the logged-in profile automatically with no environment variable. `ant` is not installed on this machine yet.
